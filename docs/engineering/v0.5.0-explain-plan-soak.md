# `v0.5.0` Explain / Plan Soak

This note records the first active-repo soak for the shipped `git-slop`
`v0.5.0` `explain` / `plan` surface.

## Repos exercised

- `git-slop`
  - local `explain` on file, folder, cluster, relationship, and top-N
  - local `plan` on folder, cluster, and relationship selectors
- `deeptravel`
  - normal repo-local `./scripts/git_slop.sh find`
  - report-driven `explain` / `plan`
- `agent-tools`
  - fresh local `find`
  - report-driven `explain` / `plan`

## Repo-local accepted noise

- `git-slop`
  - checked-in report fixtures under `tests/fixtures/reports/` are legitimate
    repo-local noise for the detector queue and structural overlays
  - this did not justify detector-core changes in the soak
- `agent-tools`
  - no repo-local tuning was needed
- `deeptravel`
  - large fixture- and eval-heavy structural clusters are expected in a mature
    mixed-code-and-fixture repo
  - this did not justify detector-core changes in the soak

## Cross-repo product issues found in `v0.5.0`

- relationship planning could emit repeated same-scope slices when the selected
  relationship and its direct shared clusters described the same file pair
- folder and path explanations could surface very broad cluster memberships too
  early because the supporting-evidence path started from pre-truncated
  `build_show_payload()` memberships ordered only by raw evidence score
- broad cluster planning needed a tighter first slice so the initial proposal
  stayed reviewable instead of defaulting to an arbitrary top-5 member list

## `v0.5.1` polish scope

The follow-up polish stays inside the allowed non-detector surface:

- rank supporting relationships and clusters from the full graph evidence,
  biased toward direct local overlap and tighter clusters
- merge repeated same-scope plan slices instead of rendering them separately
- start broad cluster planning from the strongest direct relationship-backed
  slice inside the selected cluster

## Contract confirmation

The soak and the `v0.5.1` polish do **not** change:

- detector scoring
- `check` behavior
- report `schema_version: 3`
- config `schema_version: 2`
- the non-mutating, stdout-only contract of `plan`
