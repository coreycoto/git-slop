# Git Slop 0.15.0

Version 0.15.0 implements the complete 18-finding user and developer experience
audit across first-run adoption, evidence semantics, planning, portable HTML,
testing, contributor automation, and release documentation.

1. Make every default report consumer discover the Git-private first-run report,
   keep automatic ephemeral scans cacheable, and write HTML beside the selected
   report without dirtying an unadopted repository.
2. Give policy failures, interventions, observations, and advisory health
   findings stable names and dedicated `git slop list` commands.
3. Bound health summaries with explicit shown/total counts, order findings and
   annotations by review severity first, and report omitted annotation counts.
4. Separate actual test paths from workflows and validation scripts while
   preserving the latter as explicitly labeled verification surfaces.
5. Treat configured verification commands as canonical command families,
   retain focused integration-test commands, and remove broad filename-based
   `cargo test <stem>` guesses.
6. Generate the complete `0` through `4` process-exit reference from the same
   stable runtime contract used by classified errors.
7. Open portable HTML on a decision overview that routes directly to policy,
   intervention, observation, and advisory-health collections.
8. Keep selected evidence visible in a sticky master-detail layout, move it
   ahead of the table on narrow screens, and preserve keyboard focus and deep
   links.
9. Put path, maintenance score, tokens, and context bands first and keep the
   primary path column visible while horizontally scrolling wide tables.
10. Expose independent profile, classification, language, context/load,
    maintenance, and review-severity filters with URL-persisted state.
11. Add first, previous, direct-page, configurable-page-size, next, and last
    controls while retaining explicit embedded/total evidence counts.
12. Humanize machine reason codes and evidence terms, link related paths, and
    add copy controls for exact follow-up commands.
13. Make scan-receipt path dispositions disjoint and show tracked, analyzed,
    ignored, missing, binary, and undecodable counts explicitly.
14. Publish separate cold- and warm-cache time estimates with cache assumptions;
    keep the compatibility estimate conservative at the cold value.
15. Add end-to-end first-run handoff coverage plus behavior-oriented contracts
    for report navigation, independent filters, pagination, and exit semantics.
16. Make a bare invocation print successful quick-start help and add descriptions
    for every list and cache subcommand.
17. Continue hotspot decomposition by extracting list/cache argument contracts,
    overlay module roots, structural-term/test-surface helpers, report assets,
    health rendering, CLI-runtime coverage, and contributor-CI receipt logic
    into focused modules.
18. Add quiet and JSON terminal receipts to `cargo xtask ci` and document the
    contributor requirement consistently as Node.js 24 or newer.
