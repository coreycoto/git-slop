# Git Slop 0.16.0

> Safety update: 0.16.1 supersedes the optional inference behavior described
> below. Public inference is disabled by the checked-in `defer` gate, and
> provider-free context requires no Ollama or model runtime.

Version 0.16.0 implements the complete 43-finding user and developer experience
audit across first-run state, portable reporting, contributor and release
automation, internal maintainability, shareable policy packs, and the optional
local Safeguard advisor.

1. Resolve every explicit relative report path from global `--repo`, matching
   state, output, baseline, and generated-artifact path semantics.
2. Make `git slop config migrate` a byte-preserving success when configuration
   is absent or already uses schema 2.
3. Keep `doctor --bundle` Git-private before adoption while still producing a
   useful redacted diagnostic bundle.
4. Make `cache` and `prune` follow the active Git-private or durable state root,
   with an explicit marker that survives mixed first-run workflows.
5. Promote current Git-private first-run reports and cache state during `init`,
   while retaining stale evidence safely for review.
6. Present `init` as optional durable adoption rather than recovery required
   before an ordinary first scan.
7. Lead onboarding and editor documentation with plain `git slop find`; explain
   explicit ephemeral mode only where disposable behavior is requested.
8. Align the portable Agent Plugin with no-adoption first-run behavior and the
   same durable handoff contract as the native CLI.
9. Distinguish immutable report snapshots from the current repository state in
   human, Markdown, JSON, health, and HTML freshness surfaces.
10. Open HTML on observations when no policy failure, intervention, or health
    finding is available, preserving an informative default for healthy repos.
11. Emit canonical `git slop explain` and `git slop plan` follow-up commands for
    paths, relationships, and clusters.
12. Give every stable detector reason code a curated human label instead of
    leaking underscored implementation identifiers.
13. Split curated evidence, provenance, raw record JSON, and follow-up commands
    into clearly labeled HTML detail sections.
14. Add one reset control that clears query, filters, page, selection, and URL
    state consistently.
15. Present page controls and deep links as one-based user-facing pages while
    keeping zero-based slicing internal.
16. Render view-specific empty and no-match states with direct recovery or
    navigation guidance.
17. Add bounded loopback-only `html --serve`, optional `--open`, server lifetime
    limits, connection timeouts, and restrictive response headers.
18. Let the GitHub Action generate and upload portable `report.html` only in
    the explicit `full` artifact set, with stale-output failure protection.
19. Add a pull-request template covering purpose, scope, validation, contracts,
    compatibility, security/privacy, release impact, and reviewer evidence.
20. Make issue forms version- and quarter-neutral and lint future forms against
    accidentally hard-coded shipped releases or concrete planning quarters.
21. Add versioned JSON terminal receipts for contributor doctor, CI, and
    changed-surface selection without mixing progress logs into stdout.
22. Extend contributor doctor checks to writable Cargo, Rustup, npm, Homebrew,
    and Sigstore/TUF cache locations with actionable remediation.
23. Embed workspace build revision, dirty state, target, compiler, and build
    source provenance at compile time and expose it through build-info schema 2.
24. Make concise human `explain` output the default and reserve complete raw
    evidence for JSON/YAML or explicit verbose inspection.
25. Turn a bare invocation into task-oriented successful help spanning inspect,
    automation, adoption, advice, and generation workflows.
26. Document private writable `XDG_CACHE_HOME` recovery for GitHub attestation
    verification without disabling Sigstore/TUF trust.
27. Add `cargo xtask release-status` human and JSON receipts for draft readiness,
    public immutability, exact revision, and Homebrew/Scoop receiver state.
28. Split report contract I/O, schema construction, and migration into focused
    modules without changing the public report API.
29. Split Codex configuration, documentation, runtime, and validation checks
    into focused private `xtask` modules.
30. Split comparison models, deltas, payload assembly, rendering, and tests into
    independently reviewable modules.
31. Split release-manifest models, construction, identity checks, output, and
    tests while preserving one deterministic manifest contract.
32. Split report access, readiness, evidence, comparison, and consumer helpers
    out of the former report-operations monolith.
33. Split large CLI, report-export, workflow, and maintainer test aggregators
    into behavior-oriented groups with the same executable coverage.
34. Publish Action compatibility-alias warnings with a no-earlier-than removal
    date and validate the scheduled breaking-change boundary.
35. Extend repository validation across generated docs, Action docs, schema
    versions, issue forms, links, and canonical command examples.
36. Establish a two-layer advisor architecture: deterministic model-free facts
    and candidates first, separately invoked non-mutating policy advice second.
37. Publish policy-pack schema 1, additive conflict semantics, core-invariant
    precedence, deterministic digests, compatibility rules, and a data-only
    filesystem/acquisition threat model.
38. Add offline policy init, validate, test, install, select, lock, list, show,
    and remove workflows with content-addressed storage and fail-closed limits
    for traversal, symlinks, encoding, Unicode, size, and duplicate IDs.
39. Build byte-stable advice candidates, trust zones, provenance-rich bounded
    excerpts, deterministic token truncation, hostile-content delimiting, and
    cache identities from existing report/explain/plan evidence.
40. Add a provider-neutral out-of-process boundary with native Ollama and
    OpenAI-compatible Safeguard adapters, strict loopback defaults, structured
    requests, exact model identity, timeouts, size limits, and normalized errors.
41. Add `git slop advise` for path, relationship, cluster, and top-N selectors,
    context-only output, deterministic reference validation, recomputed verdicts,
    and separate currentness-checked JSON and Markdown advice artifacts.
42. Ship ten unshadowable core invariant rules, two useful example packs, static
    golden cases, mock-provider conformance, and an explicit optional live lane.
43. Add the privacy-safe, fingerprint-pinned Git Slop/`deeptravel` benchmark,
    capacity-aware 2K/4K/8K matrix, native phase timing, memory/swap and quality
    gates, bounded provider-failure termination, private manual-review workflow,
    and a fail-closed real-hardware `defer` decision for
    `openai/gpt-oss-safeguard-20b` on the 16-GB M2 Air.
